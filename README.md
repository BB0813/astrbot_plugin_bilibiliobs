# B站UP主开播监测插件

一个用于监测指定B站UP主开播状态的AstrBot插件。当监控的UP主开始直播时，插件会自动发送通知。

## 功能特性

- 🔍 **实时监控**: 自动检查监控列表中UP主的直播状态
- 📢 **开播通知**: 检测到UP主开播时立即发送通知消息
- 🖼️ **封面图通知**: 开播通知自动附带直播间封面图
- 📢 **@全体成员**: 添加监控时可启用开播@全体成员
- 👥 **会话隔离**: 每个群/会话独立管理订阅，互不影响
- 📦 **批量操作**: 支持批量添加/移除多个UP主
- 🔔 **关播通知**: 支持UP主结束直播时的通知（可选）
- 📝 **自定义模板**: 支持自定义开播/关播通知文字内容
- 🍪 **Cookie支持**: 可配置B站Cookie获得更高API限额
- 🔐 **扫码登录**: 支持管理员私聊Bot扫码登录，自动更新Cookie（v1.2.0+）
- 🔔 **失效通知**: Cookie失效时自动通知管理员
- 🛠️ **便捷管理**: 简单的命令即可添加/移除监控
- 💾 **数据持久化**: 监控配置自动保存，重启后恢复
- 🛡️ **异常处理**: 完善的错误处理和重试机制
- ⚡ **性能优化**: 智能缓存和异步处理
- 📦 **批量查询**: 一次请求批量获取多个UP主状态，降低API压力
- 🧩 **可配置**: 支持检查间隔、最大监控数、通知开关

## 安装依赖

插件需要以下Python库：

```bash
pip install aiohttp>=3.8.0 qrcode>=7.4.0 Pillow>=10.0.0
```

或使用 requirements.txt：

```bash
pip install -r requirements.txt
```

## 使用方法

### 基本命令

#### 1. 添加监控
```
/添加监控 <UP主UID> [at_all]
```
例如：`/添加监控 123456` 或 `/添加监控 123456 at_all`（开播时@全体成员）

#### 2. 批量添加监控
```
/批量添加监控 <UID1> <UID2> ... [at_all]
```
例如：`/批量添加监控 123456 789012 345678`

#### 3. 移除监控
```
/移除监控 <UP主UID>
```
例如：`/移除监控 123456`

#### 4. 批量移除监控
```
/批量移除监控 <UID1> <UID2> ...
```
例如：`/批量移除监控 123456 789012`

#### 5. 查看监控列表
```
/监控列表
```
显示当前会话中所有监控的UP主及其直播状态

#### 6. 手动检查直播状态
```
/检查直播 <UP主UID>
```
例如：`/检查直播 123456`

#### 7. 查看插件状态
```
/插件状态
```
显示插件当前运行状态，包括HTTP会话、监控任务、监控数量等信息

#### 8-11. 通知开关
```
/开启通知          # 开启所有通知（开播与关播）
/关闭通知          # 关闭所有通知
/开启关播通知      # 仅开启关播通知
/关闭关播通知      # 仅关闭关播通知
```

#### 12. Cookie续期（v1.2.0+）

**管理员私聊Bot使用：**

```
更新cookie
b站登录
bilibili登录
更新b站cookie
```

发送以上任意命令后，Bot会返回登录二维码（图片+文本链接），使用B站客户端扫码后即可自动更新Cookie。

**首次设置管理员：**
- 管理员首次私聊Bot发送任意消息，系统会自动记录管理员身份
- Cookie失效时，会自动向管理员发送私聊通知

### Cookie续期流程

1. **首次设置**：管理员私聊Bot发送任意消息（会自动记录）
2. **Cookie失效检测**：插件检测到Cookie失效时，自动向管理员发送私聊通知
3. **扫码登录**：管理员回复 `更新cookie` 或 `b站登录`
4. **获取二维码**：Bot返回登录二维码（3分钟有效期）
5. **扫码确认**：使用B站客户端扫码登录
6. **自动更新**：Cookie自动更新到插件配置，无需重启

### 配置项

可在插件配置中设置以下选项：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `check_interval` | int | 60 | 监控检查间隔（秒） |
| `max_monitors` | int | 50 | 每个会话最大监控UP主数量 |
| `enable_notifications` | bool | true | 是否启用开播通知 |
| `enable_end_notifications` | bool | true | 是否启用关播通知 |
| `bilibili_cookie` | string | "" | B站Cookie（可选，提高API限额） |
| `live_notify_template` | string | (见默认) | 开播通知模板 |
| `end_notify_template` | string | (见默认) | 关播通知模板 |

#### 通知模板占位符

- `{uname}` - UP主名称
- `{title}` - 直播标题
- `{room_id}` - 直播间号

封面图会自动附带，无需在模板中手动添加。

### Docker部署说明

插件配置文件已自动保存到AstrBot数据目录（`data/plugins/bili_live_notice/`），确保AstrBot的 `data` 目录已正确挂载即可。

### 如何获取UP主UID

1. 打开UP主的B站主页
2. 查看URL中的数字部分，例如：`https://space.bilibili.com/123456` 中的 `123456` 就是UID
3. 或者在UP主主页按F12打开开发者工具，在Console中输入：`window.__INITIAL_STATE__.mid`

## 工作原理

1. **API调用**: 使用B站官方API `https://api.live.bilibili.com/room/v1/Room/get_status_info_by_uids` 获取直播状态
2. **状态监控**: 后台任务定期检查所有监控UP主的直播状态
3. **变化检测**: 对比当前状态与缓存状态，检测开播/关播事件
4. **通知发送**: 检测到开播/关播时发送通知消息（含封面图）
5. **限流处理**: 检测到 429 限流后动态扩大发起间隔，并对单UID错误进行退避与跳过
6. **会话隔离**: 每个群/会话独立管理订阅列表和通知
